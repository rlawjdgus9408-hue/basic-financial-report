# RAW 시트 작성 규칙

RAW 시트는 원본 재무제표를 엑셀로 옮긴 "전사본"이다.
분석·판단·재분류는 하지 않는다. 그 작업은 Analysis 시트의 몫이다.
RAW가 틀리면 이후 코멘트·재무지표·ES가 모두 틀리므로, 이 단계의 기준은 속도보다 정확성이다.

---

## 1. 원칙 5가지

1. **누락 금지.** 원본에 있는 모든 계정 행을 옮긴다. 금액이 0원이어도 원본에 행이 있으면 포함한다.
2. **원본 그대로.** 계정명·순서·로마자 대분류 표기(I. 유동자산 등)를 원본대로 쓴다.
   계정을 합치거나 나누거나 이름을 바꾸지 않는다.
3. **수정 금지, 보고.** 원본 합계가 세부 합과 맞지 않아도 숫자를 고치지 않는다.
   원본 값을 그대로 넣고, 불일치를 검증 결과로 보고한다.
4. **추정 금지.** 판독이 안 되는 숫자·계정은 "확인 불가"로 표시하고 사용자에게 묻는다.
5. **검증 통과 후 전달.** `check_raw.py`에서 ERROR가 남아 있으면 파일을 넘기지 않는다.
   단, 원본 자체의 불일치(원칙 3)는 예외로 하고 보고서에 명시한다.

---

## 2. 입력 자료와 우선순위

| 우선순위 | 자료 | 비고 |
|---|---|---|
| 1 | 표준재무제표증명(홈택스 발급) | 세무서 신고 기준, 가장 신뢰도 높음 |
| 2 | 회사 결산 재무제표(세무대리인 작성) | 세부 계정이 더 자세한 경우가 많음 |
| 3 | 이미지·스캔본 | 판독 오류 위험, 합계 검증 필수 |

- 두 자료가 모두 있으면 1을 기준으로 옮기고, 2와 금액이 다른 계정을 목록으로 보고한다.
- 연도별로 파일이 나뉘어 있으면 연도마다 추출한 뒤 계정을 합친다(§3-2).
- PDF 추출은 pdf-reading 스킬을 먼저 확인한다. 스캔본이면 이미지로 보고 판독한다.

## 3. 시트 구조

### 3-1. 블록 순서

한 시트 안에 아래 순서로 블록을 쌓는다. 블록 사이는 빈 행 2개.

1. 재무상태표
2. 손익계산서
3. 제조원가명세서 (원본에 있을 때만)
4. 이익잉여금처분계산서(또는 결손금처리계산서) (원본에 있을 때만)

### 3-2. 열 구성

| 열 | 내용 |
|---|---|
| A | 여백(좁게) |
| B | 계정과목 |
| C 이후 | 연도. **왼쪽이 전기, 오른쪽이 당기** |

- 연도 헤더 형식: `제N기(YYYY)`. 기수를 모르면 `YYYY`만 쓴다.
- 연도 수는 자료대로 한다(2개년이면 2열, 3개년이면 3열).
- 한 연도에만 있는 계정도 행으로 만들고, 없는 연도 칸은 0으로 넣는다(표시는 "-").
- 계정 순서는 가장 최근 연도 원본 순서를 기준으로 하고, 과거 연도에만 있는 계정은 원래 위치(같은 상위 계정 안)에 끼워 넣는다.

### 3-3. 행 계층(level)

| level | 의미 | 예 |
|---|---|---|
| 0 | 총계 | 자산총계, 부채총계, 자본총계, 부채와자본총계 |
| 1 | 로마자 대분류 | I. 유동자산, III. 매출총이익, V. 영업이익 |
| 2 | 중분류 | (1) 당좌자산, (2) 재고자산, 유형자산 |
| 3 | 세부 계정 | 현금및현금성자산, 매출채권, 급여 |
| 4 | 세부의 세부 | 원본에 한 단계 더 있을 때만 |

level은 검증 스크립트가 "상위 = 하위 합"을 확인하는 데 쓴다. 원본의 들여쓰기·번호 체계를 보고 정한다.

### 3-4. 금액과 부호

- 단위는 **원**. 원본이 천원·백만원이면 원으로 환산하지 않고 사용자에게 먼저 알린다.
- 금액은 원본 값을 **숫자 값**으로 넣는다. 합계 행도 원본 값을 넣고 SUM 수식은 쓰지 않는다.
  - 이유: RAW는 원본 대조용 전사본이다. 수식을 넣으면 원본 합계 오류가 가려지고,
    과거 SUM 범위가 어긋나 부채·자본 총계가 틀어진 사례가 있었다.
- 차감 계정(대손충당금, 감가상각누계액, 정부보조금, 기말재고액 등)은 원본 표기대로 넣고,
  검증 입력(JSON)에 `"sign": -1`을 붙여 합계 계산에서 빼도록 한다.
- 원본에 괄호·△로 표시된 음수(손실, 결손금)는 음수 값으로 넣는다.

### 3-5. 서식

- 글꼴: 맑은 고딕 10pt. level 0·1 행과 블록 제목·헤더는 볼드.
- 숫자 서식: `#,##0;(#,##0);"-"` (천 단위 콤마, 음수 괄호, 0은 "-")
- 블록 제목 행 오른쪽 끝에 `(단위: 원)` 표기.
- 틀 고정: 헤더 행 아래, B열 오른쪽.
- 기존 양식 파일(예: 올클래드 워크북)이 주어지면 그 파일의 서식·열너비가 이 절보다 우선한다.

## 4. 작업 절차

1. **자료 확인**: 파일 종류, 연도 수, 단위, 제조원가명세서·처분계산서 유무를 먼저 적는다.
2. **추출**: 원본을 읽어 `raw_input.json`을 만든다(형식은 §5).
   계정 수를 원본 페이지별로 세어 JSON 행 수와 맞는지 확인한다.
3. **검증**: `python scripts/check_raw.py raw_input.json`
   - ERROR가 추출 실수면 JSON을 고쳐 다시 돌린다.
   - ERROR가 원본 자체의 불일치면 고치지 않고 보고 목록에 올린다.
4. **작성**:
   - 새 파일: `python scripts/build_raw.py raw_input.json out.xlsx`
   - 기존 워크북에 넣기: `python scripts/build_raw.py raw_input.json 기존.xlsx --into`
     (RAW 시트만 채운다. 다른 시트와 서식은 건드리지 않는다. RAW에 내용이 있으면 멈춘다)
   - 스크립트는 작성 후 엑셀을 다시 읽어 JSON 값과 한 칸씩 대조한다.
5. **보고**: 아래 형식으로 짧게 보고한다.

```
[RAW 작성 결과]
자료: 표준재무제표증명 2024·2025 (2개년), 단위 원
블록: 재무상태표 58행 / 손익계산서 80행 / 이익잉여금처분계산서 9행 (제조원가명세서 없음)
검증: 이상 없음  ← 또는 불일치 항목 나열
원본 간 차이: (자료가 2종일 때만) 계정명·연도·금액 차이
확인 불가: (있을 때만) 판독 안 된 항목
```

"이상 없음"이 아니면 원인을 추정해서 쓰지 않는다. 어느 행에서 얼마가 차이 나는지만 쓴다.

## 5. 입력 JSON 형식

```json
{
  "company": "(주)예시",
  "unit": "원",
  "source": "표준재무제표증명(홈택스) 2024·2025",
  "years": ["제5기(2024)", "제6기(2025)"],
  "statements": [
    {
      "title": "재무상태표",
      "rows": [
        {"name": "I. 유동자산", "level": 1, "values": [1585046059, 3603148710]},
        {"name": "매출채권", "level": 3, "values": [491417429, 900744403]},
        {"name": "대손충당금", "level": 3, "values": [4914174, 9007444], "sign": -1}
      ]
    }
  ]
}
```

- `values`는 `years` 순서(전기 → 당기)와 같다.
- `title`은 "재무상태표", "손익계산서", "제조원가명세서", "이익잉여금처분계산서" 중 하나를 쓴다.
  검증 스크립트가 이 이름으로 블록을 구분한다.
- 판독 불가 금액은 `null`로 넣고 `"note": "확인 불가"`를 붙인다.

## 6. 검증 항목 (check_raw.py)

| 구분 | 항목 |
|---|---|
| 구조 | 연도 수와 values 길이 일치, level 범위, 빈 계정명, 같은 블록 내 중복 계정명 |
| 합계 | 모든 상위 행 = 바로 아래 level 행들의 합 (sign 반영) |
| 재무상태표 | 자산총계 = 유동+비유동, 부채총계 = 유동+비유동, 자산총계 = 부채총계+자본총계 |
| 손익계산서 | 매출총이익 = 매출액−매출원가, 영업이익 = 매출총이익−판관비, 법인세차감전 = 영업이익+영업외수익−영업외비용, 당기순이익 = 법인세차감전−법인세 |
| 블록 간 | 손익계산서 당기순이익 = 처분계산서 당기순이익, 제조원가명세서 당기제품제조원가 = 매출원가 내 당기제품제조원가 |
| 경고 | 전 연도 0원 행, null 값, 이익잉여금 불일치(적립금 있으면 정상일 수 있음) |

스크립트가 잡지 못하는 것: **원본에 있는데 JSON에 아예 없는 계정**.
합계가 맞아도 세부 계정 하나를 빼고 다른 계정에 금액을 합쳐 넣었으면 통과한다.
그래서 절차 2의 "원본 계정 수 = JSON 행 수" 대조를 반드시 사람 눈으로 한 번 한다.

## 7. 자주 틀리는 지점

- 표준재무제표증명은 연도별로 계정 코드·명칭이 조금씩 다를 수 있다(예: 상품매출 / 상품매출액).
  같은 계정인지 확실하지 않으면 합치지 말고 별도 행으로 둔 뒤 보고한다.
- 매출원가 세부(기초재고 + 당기매입 − 기말재고)의 기말재고에 `sign: -1`을 빠뜨리기 쉽다.
- 영업외비용 안의 이자비용은 이후 이자보상배수 계산에 쓰이므로 반드시 별도 행으로 둔다.
- 가수금·가지급금·대여금·임원 관련 계정은 금액이 작아도 반드시 옮긴다(Analysis 필수 묶음).
- 이익잉여금처분계산서의 전기오류수정손익은 손익계산서를 거치지 않는 항목이다. 누락하지 않는다.
