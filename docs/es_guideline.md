# Executive Summary(종합의견) 작성 규칙

그로스파이낸스 기초재무진단보고서의 Executive Summary(종합의견, ES)를 작성·수정·검수할 때
반드시 적용하는 이사님 편집 기준.

"ES", "Executive Summary", "종합의견", "exec_summary", "ES 초안", "ES 고쳐줘", "ES 검토" 언급 시,
또는 재무분석 결과(재무제표·재무비율·계정 코멘트)를 요약해 보고서 첫 페이지 문단을 만들 때 즉시 사용한다.
보고서 템플릿의 `{{ exec_summary }}` 필드를 채우는 작업도 포함한다.
작성 후에는 `scripts/check_es.py`로 반드시 자동 검수한다.

모든 규칙은 이사님이 초안을 수정한 패턴에서 도출됐다. 규칙 간 충돌 시 "우선순위" 절을 따른다.

ES는 "읽는 문서"이고 본문(표·차트)은 "확인하는 문서"다. ES가 본문의 축소판이 되면 이사님은 그 부분을
삭제한다. 이 구분이 모든 규칙의 출발점이다.

## 0. 작성 전 선행 조건 (건너뛰지 말 것)

ES를 쓰기 전에 아래 세 가지가 확보돼 있어야 한다. 없으면 먼저 산출하거나 사용자에게 요청한다.

- **재무비율 산출 결과**: 활동성 비율은 기말 잔액 기준(평균 잔액 아님).
- **적자·악화 연도의 원인 분해**: 당기순손익이 적자 전환됐거나 크게 악화된 연도가 있으면, 영업 단계
  (매출·원가·판관비)와 영업외 단계(이자비용·외환손익·기타)로 나눠 전년 대비 증감액 1위 항목을 식별한다.
  지표가 나쁘다는 이유만으로 원인을 지목하지 않는다.
  - 예: 이자비용 +6백만, 외화환산손실 신규 +82백만 → 주 요인은 외화환산손실이다.
- **사전 검토사항 10개 문항 응답**: "개선 필요(아니오)" 개수를 센다. 5개 이상이면 3단락에 반영(§3-3).

확인되지 않은 사실은 추정해서 쓰지 않는다. "확인 불가"로 남기고 사용자에게 묻는다.

## 1. 구조

- 분량: A4 1페이지 이내, 전체 약 700~900자, 단락당 4~5문장 이내.
- 기본 3단락. 양호 영역이 많아 1~2단락에 압축되지 않을 때만 4단락으로 확장한다.

| 단락 | 역할 | 핵심 질문 | 종결 표현 |
|---|---|---|---|
| 1 | 회사 분석 | 어떤 회사이고, 무엇이 일어났는가 | ~로 진단됩니다 / ~로 판단됩니다 |
| 2 | 인사이트 | 데이터에서 도출되는 핵심 통찰은 무엇인가 | ~로 평가됩니다 / ~확인됩니다 |
| 3 | 운영 관리 측면의 보완사항 | 향후 운영에서 보완할 지점은 | ~보완이 필요한 시점으로 보입니다 |

4단락 확장형: 1 회사 분석 / 2 인사이트 / 3 주요 사항(재무 안정성·자본 구조·운전자본) / 4 보완사항.

문단 내부 흐름: Fact(수치) → Diagnosis(판정) → Impact(현금·마진 영향) → Control(관리 방향).

## 2. 단락별 작성 규칙

### 2-1. 1단락 (회사 분석)

첫 문장은 회사 정체성으로 시작한다. 매출·이익 수치로 시작하지 않는다.

- ✗ "(주)○○는 매출이 27.6억에서 104억으로 376% 증가, 영업이익도 … 고성장 단계의 기업입니다."
- ✓ "(주)○○는 사업 실질은 [업종 정의]가 손익을 견인하는 사업 모델로 판단됩니다. 3개년 동안 매출이
  27.6억에서 104억으로 376% 증가 …"

도입구로 "공유해 주신 데이터를 근거로 하면,"을 붙이는 것은 허용한다. 단, 바로 뒤에 정체성 정의가 와야 한다.

정체성 정의 우선순위:
1. 사업자등록상 업종과 실질이 다르면 실질 정의를 쓴다.
2. 매출 구성 중 손익을 견인하는 축을 먼저 쓴다(제품 / 공사 / SW 등).
3. 회사소개서·등록증에서 핵심 사업 키워드를 가져온다.

### 2-2. 2단락 (인사이트)

- 수익성 메커니즘(예: 매출총이익률과 판관비율의 시소)처럼 데이터가 보여주는 핵심을 1개 잡는다.
- 화살표(X%→Y%)는 이 단락의 시소 메커니즘에 우선 배정한다(§4-2).
- 강점 서술은 2~3문장으로 제한한다. 줄여야 할 때는 전망성 부연 문장부터 삭제한다.

### 2-3. 3단락 (보완사항)

- 보완사항은 최대 2가지. ①②③ 번호를 붙이지 않고 자연어로 잇는다.
  - 1가지: 가장 두드러진 지점 하나만 있을 때
  - 2가지: 영역이 다를 때(예: 본업 수익성 + 재무관리 체계)
  - 3가지 이상: 본문 부문별 진단으로 넘긴다.
- 해결 방법을 상세히 쓰지 않는다. "~분해 / ~정립" 같은 실행 동사는 본문에 맡긴다.
- 앞 단락의 수치를 다시 인용하지 않는다. 이 단락은 수치가 아니라 체계·방향으로 닫는다.
- 마무리는 "방향 + 괄호 예시" 톤으로 쓴다.
  - 예: "월단위 손익·자금 모니터링 체계(재무Report, 예산/리스크 관리 등)의 보완이 필요한 시점으로 보입니다."
- 서비스·구독 상품명(그로스파이낸스, 구독형 재무팀, CFO 서비스 등)을 쓰지 않는다. 방향만 암시한다.

### 2-4. 각 단락 마무리 1줄

사실로만 끝내지 않고 "향후 무엇이 중요한가"를 1줄 덧붙인다.

| 단락 | 마무리 패턴 예 |
|---|---|
| 1 | "~에 대한 확장 혹은 효율 증대의 고민이 시작되는 시점으로 판단됩니다" |
| 2 | "~효율성 유지가 향후 손익 관리의 핵심 요인으로 보입니다" |
| 3 | "~보완이 필요한 시점으로 보입니다" |

## 3. 내용 판단 규칙

### 3-1. 압축 우선순위

| 영역 | 분량 |
|---|---|
| 양호 영역(운전자본 안정, 정합성 확보 등) | 한 줄로 압축. 예: "운전자본 등도 양호한 상황으로 진단됩니다" |
| 변화·전환 영역(외형 급증, 사업 구조 전환) | 수치 3~5개와 함께 구체 기술 |
| 리스크·보완 영역 | 수치 + 의미 + 시사 1줄. 양호 영역보다 상세하게 |

- ES 전체 수치는 핵심 5~10개로 제한한다.
- 괄호 속 세부 구성(예: "자본금 1.5억 유상증자 + 이익잉여금 누적 8.2억"), 구체 회전일수 등은 본문 표로 넘긴다.
- 같은 수치를 두 단락 이상에서 반복하지 않는다. 한 수치는 ES 전체에서 한 번만 쓴다.

### 3-2. 인과 단정 금지

- 단일 지표를 적자·부실의 원인으로 못박지 않는다. "점검 필요" 형태로 완충한다.
  - ✗ "이자보상배수가 1배를 밑돌아 … 이는 적자 전환의 배경으로 평가됩니다."
  - ✓ "영업이익 대비 이자비용이 관리 가능한 수준으로 발생하고 있는지 지속적인 점검이 필요합니다."
- 원인을 쓸 때는 §0-2 분해 결과(증감 기여도 1위 항목)에 근거한다.
- 참고: 계정 셀 코멘트에서는 확인된 수치 인과("외화환산손실 전환으로 당기순손실")를 단정해도 된다.
  ES와 셀 코멘트의 톤은 다르다.
- 성장 국면이라도 비용 증가에 대한 효율성 기준을 완화하지 않는다.
- 유동비율이 높으면 구성(현금 / 매출채권 / 선급금 / 재고)을 확인한 뒤에 양호 판정을 쓴다.

### 3-3. 체크리스트 ↔ ES 연결

사전 검토사항 10개 중 "개선 필요"가 5개 이상이면 3단락에 재무관리 체계 도약 관점을 1줄 넣는다.

| 개선 필요 문항 | ES 연결 표현 |
|---|---|
| 매월 재무성과 보고 X | 월단위 재무Report 체계 |
| 재무계획·예산 X | 재무계획을 통한 예산/리스크 관리 |
| 재무 리스크 대응 X | 재무관리 체계 도약 |

예: "회사의 성장에 따라 월단위의 손익과 자금을 모니터링할 수 있는 재무Report 체계와 재무계획을 통한
예산/리스크 관리 등 재무관리 체계도 한 단계 도약이 필요한 시점으로 보입니다."

## 4. 표기 규칙

### 4-1. 금액 단위 (한국식 "억+천만")

| 금액대 | 표기 | 예 |
|---|---|---|
| 1억 이상, 천만 단위 있음 | X.X억 | 538백만원 → 5.4억 |
| 1억 이상, 천만 단위 없음 | X억 | 800백만원 → 8억 |
| 1천만~1억 미만 | X천Y백만 | 78백만원 → 7천8백만 |
| 1천만 미만 | X백만 | 6백만원 → 6백만 |

만·십만 단위는 절삭한다. "백만원" 단위 표기는 ES에 쓰지 않는다.

### 4-2. 화살표

ES 전체에서 X%→Y% 형태는 최대 2개. 나머지는 자연어로 바꾼다.

- "182.4%에서 125.7%로 3년 연속 개선" (✗ 182.4%→125.7%)

### 4-3. 영어 약어 금지

| 약어 | 한글 |
|---|---|
| GPM | 매출총이익률 |
| OPM | 영업이익률 |
| NPM | 순이익률 |
| DSO | 매출채권 회수기간 |
| DIO | 재고자산 회전일수 |
| DPO | 매입채무 결제기간 |
| CCC | 현금전환주기 |

ROA·ROE는 한글을 병기한다: "ROA(자산이익률)".

### 4-4. 금지 표현

"착시", "도산", "부재", "폭발적", "사상 최대", "잠식", "이대로 가면", "~시사합니다",
"~가능성이 있습니다", "~하세요", "이익의 질", "매출 mix", "매출 주도형 성장",
사실로 확정되지 않은 "구조적 전환".

| 금지 | 대체 |
|---|---|
| 이익의 질 | 문장 삭제 또는 사실 기술 |
| 매출 mix 개선 | "공사 부문이 손익을 견인" 등 구체 사실 |
| 구조적 전환 | "사업 구조 전환"(이미 사실인 경우만) |

### 4-5. 종결 표현

- 격식체(~입니다/~습니다)를 유지하고, 종결 표현을 4종 이상 섞는다
  (진단됩니다 / 판단됩니다 / 평가됩니다 / 확인됩니다 / 보입니다 / 필요합니다).
- 모든 단락을 "필요합니다"로 끝내지 않는다.
- 헤지 없는 단정 마무리("~필요합니다" 단독)는 ES 전체에서 1문장만 허용한다. 나머지는
  "~필요한 시점으로 보입니다", "~시점으로 판단됩니다"처럼 완충한다.

## 5. 차트와의 정렬

- 차트는 Claude가 직접 만들지 않고 권고만 한다(어떤 차트 / 어떤 데이터 / 어떤 메시지).
- ES 메시지를 받쳐주는 차트 2개를 고른다. 우선순위: ① 2단락 수익성 메커니즘 ② 자본 구조 변화.

## 6. 작업 절차

1. §0 선행 조건 확인.
2. 단락별 핵심 메시지를 한 줄씩 먼저 정한다(사용자에게 보여줄 필요는 없음).
3. 초안 작성.
4. 초안을 텍스트 파일로 저장하고 자동 검수를 돌린다.
   ```bash
   python scripts/check_es.py es_draft.txt
   ```
   ERROR는 반드시 고치고, WARN은 하나씩 판단해 고치거나 유지 사유를 적는다.
5. §7 수동 체크리스트를 확인한다(스크립트가 못 잡는 항목).
6. 보고서에 넣을 때는 템플릿의 `{{ exec_summary }}` 필드만 채운다. 템플릿 구조·서식은 건드리지 않는다.
   업로드된 파일은 직접 열어 수정하고, 처음부터 다시 생성하지 않는다.

## 7. 수동 체크리스트 (스크립트가 판단하지 못하는 항목)

- [ ] 첫 문장이 회사 정체성(사업 실질)으로 시작하는가
- [ ] 적자·악화 원인이 증감 기여도 1위 항목과 일치하는가
- [ ] 단일 지표를 원인으로 단정한 문장이 없는가
- [ ] 양호 영역은 한 줄, 리스크 영역은 상세한가
- [ ] 강점 서술이 2~3문장 이내이고 전망성 부연이 없는가
- [ ] 보완사항이 2가지 이하이고 해결 방법을 상세히 쓰지 않았는가
- [ ] 3단락이 수치가 아니라 체계·방향으로 닫히는가
- [ ] 체크리스트 "개선 필요" 5개 이상이면 재무관리 체계 문장이 있는가
- [ ] 서비스·구독 명칭 없이 방향만 암시했는가

## 우선순위 (규칙이 충돌할 때)

1. 사실 정확성(추정 금지, 원인 분해 근거) — 항상 최우선
2. 이 파일의 규칙
3. 고객사별 프로젝트 지침·이사님 개별 피드백이 있으면 그것이 이 파일보다 우선한다. 새 피드백을 받으면
   이 파일에 반영하고 변경 이력에 남긴다.
