# Executive Summary 작성 규칙

기초재무진단보고서 첫 페이지 <종합의견>({{ exec_summary }})에 들어갈 글을 쓰는 규칙이다.
모든 규칙은 이사님이 초안을 수정한 패턴에서 도출됐다. 규칙 간 충돌 시 "우선순위" 절을 따른다.

ES는 "읽는 문서"이고 본문(표·차트)은 "확인하는 문서"다.
ES가 본문의 축소판이 되면 이사님은 그 부분을 삭제한다. 이 구분이 모든 규칙의 출발점이다.

읽는 사람은 문단마다 "그래서 뭐라는 거야?"를 묻는다. 각 단락은 결론이 먼저 읽혀야 하고, 중요한 것만 남긴다.

---

## 0. 작성 전 선행 조건 (건너뛰지 말 것)

ES를 쓰기 전에 아래가 확보돼 있어야 한다. 없으면 먼저 산출하거나 사용자에게 요청한다.

1. **재무비율 산출 결과**: 활동성 비율은 기말 잔액 기준(평균 잔액 아님).
2. **적자·악화 연도의 원인 분해**: 당기순손익이 적자 전환됐거나 크게 악화된 연도가 있으면,
   영업 단계(매출·원가·판관비)와 영업외 단계(이자비용·외환손익·기타)로 나눠
   전년 대비 증감액 1위 항목을 식별한다. 지표가 나쁘다는 이유만으로 원인을 지목하지 않는다.
   - 예: 이자비용 +6백만, 외화환산손실 신규 +82백만 → 주 요인은 외화환산손실이다.
   - 제조업 원가율 변동은 투입원가율(당기총제조비용 ÷ 매출)과 재고변동 효과로 나눠 판단한다. 상쇄되는 개별 항목(원재료↑·외주↓)을 원인으로 지목하지 않는다.
3. **사전 검토사항 10개 문항 응답**: "개선 필요(아니오)" 개수를 센다. 5개 이상이면 3단락에 반영(§3-4).
4. **계정 코멘트 확정**: 코멘트가 확정된 뒤 ES를 쓴다. 이후 코멘트가 바뀌면 ES의 해당 수치·방향 표현을 함께 고친다.
5. **함께 제출되는 산출물 확인**: 재무비율 분석 파일 등이 같이 나가면, ES에 쓰는 수치가 그 파일과 같은 정의·같은 값인지 확인한다(예: 재고 효과 "약 8할" vs "4.9%p"처럼 정의가 다른 수치가 섞이지 않게).
6. **문서 용도 확인**: 고객 전달(사전 상담) 문서인지 내부 검토 문서인지 확인한다.
7. **근거 범위 = 보고서 지면** (v1.2): ES 수치·판단의 근거는 고객이 받는 보고서 안에서 찾을 수 있어야 한다. 보고서 본문은 Analysis 표(노출 행 + 코멘트 + 지표)와 사전 검토사항이다. Graph 시트, 숨김 행, 내부 분석 파일(재무비율 분석 등)에만 있는 수치는 지면 밖이다.
   - 지면 밖 수치는 ES에서 빼고 결론만 남기거나, 그 수치가 핵심이면 Analysis에 행·코멘트로 노출시킨 뒤 쓴다.
   - 예: 영업손익 증감 분해 "매출총이익 감소 효과 53.8억"(Graph에만 있음) → 삭제, "적자 확대의 주 요인은 매출 감소로 확인됩니다"만 유지.
8. **고객 제공 자료 선독** (v1.2): 체크리스트 응답, 기존 시스템 기재란, 스크린샷, IR 자료를 먼저 읽고 고객이 이미 운영 중인 체계를 목록화한다. 이미 하고 있는 일을 보완사항으로 권하지 않고, "예"로 답한 문항과 모순되는 문장을 쓰지 않는다.
   - 예: 월간 리포트·재무계획·자금계획 "예" + 공헌이익 대시보드 운영 → "월단위 손익·자금 리포트 보완", "브랜드별 공헌이익 관리 도입"은 쓰지 않는다.

확인되지 않은 사실은 지어내서 쓰지 않는다. "확인 불가"로 남기고 사용자에게 묻는다.

## 1. 구조

- 분량: 기본 약 700~1,100자, 단락당 4~5문장 이내. 사용자가 분량을 지정하면 그 값을 **상한**으로 보고 −10%까지 허용한다(예: 1,100자 → 990~1,100자). **분량을 채우려고 문장을 추가하지 않는다.** 이사님은 분량보다 군더더기 제거를 우선한다(더블유아일랜드: 초안 1,147자 → 최종 1,021자).
- 기본 3단락. 양호 영역이 많거나 재무 안정성·운전자본을 따로 다뤄야 하면 4단락으로 확장한다.
- 보고서 템플릿에 넣을 때는 한 줄(불릿 행)에 한 논점만 담는다. 단락이 두 논점이면 두 행으로 나눈다(예: 1단락 = 현황 / 원인 추론, 2단락 = 첫째 원인 / 둘째 원인·결론).

| 단락 | 역할 | 핵심 질문 | 종결 표현 |
|---|---|---|---|
| 1 | 회사 분석 | 어떤 회사이고, 무엇이 일어났는가 | ~로 진단됩니다 / ~로 판단됩니다 |
| 2 | 인사이트 | 데이터에서 도출되는 핵심 통찰은 무엇인가 | ~로 평가됩니다 / ~확인됩니다 |
| 3 | 운영 관리 측면의 보완사항 | 향후 운영에서 보완할 지점은 | ~보완이 필요한 시점으로 보입니다 |

4단락 확장형: 1 회사 분석 / 2 인사이트 / 3 주요 사항(재무 안정성·자본 구조·운전자본) / 4 보완사항.

문단 내부 흐름: Fact(수치) → Diagnosis(판정) → Impact(현금·마진 영향) → Control(관리 방향).

## 2. 단락별 작성 규칙

### 2-1. 1단락 (회사 분석)

**첫 문장은 회사 정체성으로 시작한다. 매출·이익 수치로 시작하지 않는다.**

- ✗ "(주)○○는 매출이 27.6억에서 104억으로 376% 증가, 영업이익도 … 고성장 단계의 기업입니다."
- ✓ "(주)○○는 사업 실질은 [업종 정의]가 손익을 견인하는 사업 모델로 판단됩니다. 3개년 동안 매출이 27.6억에서 104억으로 376% 증가 …"
- 도입구로 "공유해 주신 데이터를 근거로 하면,"을 붙이는 것은 허용한다. 단, 바로 뒤에 정체성 정의가 와야 한다.

정체성 정의 우선순위:
1. 사업자등록상 업종과 실질이 다르면 실질 정의를 쓴다.
2. 매출 구성 중 손익을 견인하는 축을 먼저 쓴다(제품 / 공사 / SW 등).
3. 회사소개서·등록증에서 핵심 사업 키워드를 가져온다.
4. **구체성은 자료가 뒷받침하는 범위까지만.** 매출 구성 자료 없이 종목 중 특정 품목을 대표로 앞세우지 않고 상위 범주로 쓴다.
   - ✗ "기저귀 등 유아용품을 …"(종목: 기저귀·유아용품·임산부용품·의류, 매출은 제품매출 단일)
   - ✓ "유아용품을 자체 브랜드로 생산·판매하는 제조 기업으로 …"
5. **제품 형태 묘사보다 브랜드·업(業) 포지션을 쓴다** (v1.2). 회사소개 자료의 제품 설명을 옮기지 않는다.
   - ✗ "귀에 붙이는 주얼리 패치 브랜드 윙블링(wbL)을 중심으로 한 전자상거래 기업"
   - ✓ "주얼리 브랜드 윙블링(wbL)을 중심으로 한 전자상거래 기업"

### 2-2. 2단락 (인사이트)

- 수익성 메커니즘(예: 매출총이익률과 판관비율의 시소)처럼 데이터가 보여주는 핵심을 1개 잡는다. 원인이 둘이면 "첫째 / 둘째"로 나누고 결론 1문장으로 닫는다.
- 화살표(X%→Y%)는 이 단락의 시소 메커니즘에 우선 배정한다(§4-2).
- 강점 서술은 2~3문장으로 제한한다. 줄여야 할 때는 전망성 부연 문장부터 삭제한다.
- 사실로 확인되는 강점은 원인 분석의 근거로 활용할 수 있다(예: "인건비 비중은 21%대로 유지되어, 이익률 하락은 고정비보다 판매채널 비용에서 비롯").
- 원인 분해(§0-2)는 결론 한 문장으로 쓴다. 분해 금액(증감 기여액)은 §0-7에 따라 보고서 지면에 있을 때만 인용한다.

### 2-3. 3단락 (보완사항)

- 보완사항은 최대 2가지. ①②③ 번호를 붙이지 않고 자연어로 잇는다.
  - 1가지: 가장 두드러진 지점 하나만 있을 때
  - 2가지: 영역이 다를 때(예: 본업 수익성 + 재무관리 체계)
  - 3가지 이상: 본문 부문별 진단으로 넘긴다.
- 해결 방법을 상세히 쓰지 않는다. "~분해 / ~정립" 같은 실행 동사는 본문에 맡긴다. 처방(시기·KPI·정량 효과)이 필요하면 재무비율 분석 부록이 담당한다.
- **앞 단락의 수치를 다시 인용하지 않는다.** 이 단락은 수치가 아니라 체계·방향으로 닫는다.
- 마무리는 "방향 + 괄호 예시" 톤으로 쓴다. 단, 방향만으로 충분하면 괄호 예시는 생략한다(괄호 예시가 고객 시스템에 대한 단정으로 읽힐 위험이 있으면 생략이 우선).
  - 예: "월단위 손익·자금 모니터링 체계(재무Report, 예산/리스크 관리 등)의 보완이 필요한 시점으로 보입니다."
- **앞 단락 문제와 처방을 연결어로 잇는다** (v1.2). 2단락에서 지목한 문제를 보완사항 문장 안에 한 구절로 받아 준다.
  - 예: 2단락 "판관비율 상승" → 보완 "손익구조 개선 작업과 필요 현금흐름 예측을 바탕으로 …"
- 고객이 이미 높은 관리 수준을 갖췄으면 그것을 먼저 인정한 뒤(1문장), 보완 지점은 "점검·유효성 확인" 수준의 방향으로 쓴다.
  - 예: "…재무 데이터 관리 수준은 높은 것으로 확인됩니다. 다만 전반적인 관리 지표의 점검 및 모니터링 유효성 여부에 대한 체크가 필요한 것으로 판단됩니다."
- 서비스·구독 상품명(그로스파이낸스, 구독형 재무팀, CFO 서비스 등)을 쓰지 않는다. 방향만 암시한다.
- **고객의 언어와 연결한다.** 고객이 체크리스트·메일에서 쓴 고민과 방향을 포괄하는 표현을 쓴다.
  - 예: 투자 유치 시 지분가치 근거 부족 + 재무관리 방향 "추후 M/A" → "향후 M&A 등 IR 과정에서 지분가치를 객관적으로 설명하는 기반"

### 2-4. 각 단락 마무리 1줄

사실로만 끝내지 않고 "향후 무엇이 중요한가"를 1줄 덧붙인다.

| 단락 | 마무리 패턴 예 |
|---|---|
| 1 | "~에 대한 확장 혹은 효율 증대의 고민이 시작되는 시점으로 판단됩니다" |
| 2 | "~효율성 유지가 향후 손익 관리의 핵심 요인으로 보입니다" / "~판단하기 어려운 상황으로 평가됩니다" |
| 3 | "~보완이 필요한 시점으로 보입니다" |

### 2-5. 한 문장 한 메시지

- "필요하다"는 주장과 "그러면 이런 효과가 있다"는 주장을 한 문장에 묶지 않는다.
  - ✗ "…도약이 필요한 시점이며, 이는 향후 … 기반이 될 것으로 판단됩니다."
  - ✓ "…도약이 필요한 시점입니다. 이는 향후 … 기반이 될 것으로 판단됩니다."

### 2-6. 미래 문장은 긍정 프레이밍 (v1.2)

향후 방향을 말하는 문장은 위험의 지속이 아니라 회복·개선의 대상을 주어로 쓴다.
- ✗ "매출 회복 지연과 차입 만기에 대비한 시나리오별 대응 계획"
- ✓ "매출 회복과 차입 만기에 대비한 시나리오별 대응 계획"

## 3. 내용 판단 규칙

### 3-1. 압축 우선순위

| 영역 | 분량 |
|---|---|
| 양호 영역(운전자본 안정, 정합성 확보 등) | 한 줄로 압축. 예: "운전자본 등도 양호한 상황으로 진단됩니다" |
| 변화·전환 영역(외형 급증, 사업 구조 전환) | 수치 3~5개와 함께 구체 기술 |
| 리스크·보완 영역 | 수치 + 의미 + 시사 1줄. 양호 영역보다 상세하게 |

- ES 전체 수치는 핵심 5~10개로 제한한다(분량을 늘려도 15개 이내).
- 괄호 속 세부 구성, 구체 회전일수 등은 본문 표로 넘긴다. 필요하면 "판매까지 반년 이상"처럼 의미로 바꿔 쓴다.
- **같은 수치를 두 단락 이상에서 반복하지 않는다.** 한 수치는 ES 전체에서 한 번만 쓴다.

### 3-2. 근거 강도와 종결어 (v1.1)

문장을 쓰기 전에 근거 종류를 분류하고 종결어를 맞춘다.

| 근거 종류 | 종결어 | 예 |
|---|---|---|
| 재무제표로 계산된 사실 | ~확인됩니다 | "원가율 상승분의 약 8할이 재고 감소에서 발생 … 확인됩니다" |
| 판정 | ~진단됩니다 / ~평가됩니다 | "재무구조는 … 안정적인 상황으로 진단됩니다" |
| 소거법 등 간접 추론 | ~추정됩니다 | "세컨브랜드 지출을 줄인 뒤에도 회복되지 않았습니다. 이는 원인이 본업 내부에 있음을 보여주는 것으로 추정됩니다" |
| 가결산·고객 제공 미검증 수치 | 수치 뒤 기준 병기 | "(가결산 기준)", "(고객 제공 ERP 기준)" |
| 고객 제공 정성 정보(IR·회사소개의 입점·계약·계획 등) | 문장 끝에 고객 존칭 출처 병기 | "…중요한 시점입니다(제공해주신 자료 기반)" — "회사 제시 자료 기준으로"처럼 분석가 시점의 문두 표기는 쓰지 않는다. 미검증 수치(성장 배수 등)는 넣지 않는다 |

- "~가능성이 있습니다", "~시사합니다"는 여전히 금지한다. 간접 추론은 "추정됩니다"로 명시한다.

### 3-3. 인과 단정 금지

- 단일 지표를 적자·부실의 원인으로 못박지 않는다. "점검 필요" 형태로 완충한다.
  - ✗ "이자보상배수가 1배를 밑돌아 … 이는 적자 전환의 배경으로 평가됩니다."
  - ✓ "영업이익 대비 이자비용이 관리 가능한 수준으로 발생하고 있는지 지속적인 점검이 필요합니다."
- 원인을 쓸 때는 §0-2 분해 결과(증감 기여도 1위 항목)에 근거한다.
- 브랜드·채널별 손익처럼 자료가 없는 귀속은 "맞물려", "시점과 함께" 같은 시점 서술까지만 쓰거나 §3-2에 따라 "추정됩니다"로 명시한다.
- 참고: 계정 셀 코멘트에서는 확인된 수치 인과("외화환산손실 전환으로 당기순손실")를 단정해도 된다. ES와 셀 코멘트의 톤은 다르다.
- 성장 국면이라도 비용 증가에 대한 효율성 기준을 완화하지 않는다.
- 유동비율이 높으면 구성(현금 / 매출채권 / 미수금 / 선급금 / 재고)을 확인한 뒤에 양호 판정을 쓴다.

### 3-4. 체크리스트 ↔ ES 연결

사전 검토사항 10개 중 "개선 필요"가 5개 이상이면 3단락에 재무관리 체계 도약 관점을 1줄 넣는다.

| 개선 필요 문항 | ES 연결 표현 |
|---|---|
| 매월 재무성과 보고 X | 월단위 재무Report 체계 |
| 재무계획·예산 X | 재무계획을 통한 예산/리스크 관리 |
| 재무 리스크 대응 X | 재무관리 체계 도약 |
| 지분가치 근거 X | M&A 등 IR 과정에서 지분가치를 객관적으로 설명하는 기반 |
| 재고 장부가치 파악 X | 재고 수량과 제품별 원가 기준을 일원화한 월단위 원가 관리 체계 |

예: "회사의 성장에 따라 월단위의 손익과 자금을 모니터링할 수 있는 재무Report 체계와 재무계획을 통한 예산/리스크 관리 등 재무관리 체계도 한 단계 도약이 필요한 시점으로 보입니다."

### 3-5. 고객 내부 체계는 단정해서 평가하지 않는다 (v1.2)

스크린샷·체크리스트 기재란 등 일부 자료에서 추론한 고객 내부 시스템의 결함은 단정하지 않는다. 고객이 "그렇지 않다"고 반박할 수 있는 문장은 방향 표현으로 낮춘다.
- ✗ "관리 지표는 현재 원가율을 적용하는 등 결산 재무제표와 기준이 달라, 결산 조정까지 반영해 두 숫자를 맞추는 과정이 보완 과제로 판단됩니다(재고 실사·평가, 대손 기준, 월 결산 대사 등)."
- ✓ "다만 전반적인 관리 지표의 점검 및 모니터링 유효성 여부에 대한 체크가 필요한 것으로 판단됩니다."

### 3-6. 내부 분석과 고객 문서를 분리한다 (v1.2)

내부 분석 파일에 있는 강한 진단은 근거가 있어도 고객 ES에 쓰지 않는다. 본문·미팅으로 보낸다.
- 해당: 자본잠식 도달 시점, 런웨이 개월 수, 외부 신용등급 변동, "흑자 전환 불가" 같은 결론형 문장
- ES에는 같은 사실을 완충된 상태 서술로 쓴다: "자금 여력이 크지 않은 상황으로 진단됩니다", "결손이 쌓이면서"

## 4. 표기 규칙

### 4-1. 금액 단위 (한국식 "억+천만")

| 금액대 | 표기 | 예 |
|---|---|---|
| 1억 이상 | 소수 첫째 자리 반올림, 정수면 ".0" 생략 | 538백만원 → 5.4억 / 1,498.9백만원 → 15억 |
| 1천만~1억 미만 | X천Y백만 | 65.5백만원 → 6천5백만 |
| 1천만 미만 | X백만 | 6.5백만원 → 6백만 |

만·십만 단위는 절삭한다. "백만원" 단위 표기는 ES에 쓰지 않는다.

### 4-2. 화살표

ES 전체에서 X%→Y% 형태는 최대 2개. 나머지는 자연어로 바꾼다.
- "182.4%에서 125.7%로 3년 연속 개선" (✗ 182.4%→125.7%)
- 비교 시점이 다르면 괄호에 기간을 붙인다: "32.2%→39.8%(2026년 상반기)"

### 4-3. 영어 약어 금지

| 약어 | 한글 |
|---|---|
| GPM | 매출총이익률 |
| OPM | 영업이익률 |
| NPM | 순이익률 |
| DSO | 매출채권 회수기간 |
| DIO | 재고자산 회전일수 |
| DPO | 매입채무 결제기간 |
| CCC | 현금전환주기 |

ROA·ROE는 한글을 병기한다: "ROA(자산이익률)". M&A·IR은 실무 통용어로 허용.

### 4-4. 금지 표현

"착시", "도산", "부재", "폭발적", "사상 최대", "잠식", "이대로 가면", "~시사합니다", "~가능성이 있습니다", "~하세요",
"이익의 질", "매출 mix", "매출 주도형 성장", 사실로 확정되지 않은 "구조적 전환".

| 금지 | 대체 |
|---|---|
| 이익의 질 | 문장 삭제 또는 사실 기술 |
| 매출 mix 개선 | "공사 부문이 손익을 견인" 등 구체 사실 |
| 구조적 전환 | "사업 구조 전환"(이미 사실인 경우만) |

### 4-5. 종결 표현

- 격식체(~입니다/~습니다)를 유지하고, 종결 표현을 4종 이상 섞는다
  (진단됩니다 / 판단됩니다 / 평가됩니다 / 확인됩니다 / 추정됩니다 / 보입니다 / 필요한 시점입니다).
- 모든 단락을 "필요합니다"로 끝내지 않는다.
- 헤지 없는 단정 마무리("~필요합니다" 단독)는 ES 전체에서 1문장만 허용한다.
  나머지는 "~필요한 시점으로 보입니다", "~시점으로 판단됩니다"처럼 완충한다.

## 5. 차트·본문과의 정렬

- 차트는 Claude가 직접 만들지 않고 권고만 한다(어떤 차트 / 어떤 데이터 / 어떤 메시지). 사용자가 엑셀 차트를 요청하면 그때 만든다.
- ES 메시지를 받쳐주는 차트 2개를 고른다. 우선순위: ① 2단락 수익성 메커니즘 ② 고객 질문에 직접 답하는 분해 차트(예: 영업이익률 변동 분해) 또는 자본 구조 변화.
- 차트 제목·막대 구성이 ES 결론과 어긋나지 않게 한다(상쇄 항목은 합쳐 표시).
- 보고서 본문은 Analysis 표(계정 + 코멘트 + 지표) 이미지가 기본이다. ES 수치는 그 표의 **노출 행** 값과 같아야 한다. Graph 시트는 보고서에 들어가지 않으므로 ES 근거로 쓰지 않는다(§0-7).

## 6. 작업 절차

1. §0 선행 조건 확인.
2. 단락별 핵심 메시지(결론)를 한 줄씩 먼저 정한다(사용자에게 보여줄 필요는 없음).
3. 각 문장의 근거 종류를 분류하고(§3-2) 초안 작성.
4. 초안을 텍스트 파일로 저장하고 자동 검수를 돌린다.
   ```bash
   python scripts/check_es.py es_draft.txt
   ```
   스크립트가 없으면 같은 항목(글자 수, 화살표 개수, 수치 개수·중복, 금지어·영어 약어, 단락별 문장 수, 종결 표현 분포, "필요합니다." 단독 개수)을 인라인 코드로 직접 검사하고, 스크립트가 없었다는 사실을 보고한다.
   ERROR는 반드시 고치고, WARN은 하나씩 판단해 고치거나 유지 사유를 적는다.
5. 팩트체크: ES의 모든 수치·방향 표현을 원천 데이터·계정 코멘트·함께 제출되는 산출물과 대조한다(기간 혼동 — 예: "일부 회복" vs 실제 "재감소" — 확인).
6. §7 수동 체크리스트를 확인한다(스크립트가 못 잡는 항목).
7. 보고서에 넣을 때는 템플릿의 {{ exec_summary }} 필드만 채운다. 템플릿 구조·서식은 건드리지 않는다.
   업로드된 파일은 직접 열어 수정하고, 처음부터 다시 생성하지 않는다.
8. 수정 요청을 받으면 바뀌어야 할 문장만 고치고, 수정 범위를 한 줄로 되짚는다. 이미 검증된 문장을 다시 생성하지 않는다.

## 7. 수동 체크리스트 (스크립트가 판단하지 못하는 항목)

- [ ] 첫 문장이 회사 정체성(사업 실질)으로 시작하고, 자료 범위를 넘는 구체화(특정 품목)가 없는가
- [ ] 각 단락의 결론이 먼저 읽히는가("그래서 뭐라는 거야?"에 답하는가)
- [ ] 적자·악화 원인이 증감 기여도 1위 항목과 일치하는가
- [ ] 단일 지표를 원인으로 단정한 문장이 없는가
- [ ] 종결어가 근거 강도(계산/판정/추론)와 맞는가. 간접 추론에 "추정됩니다"가 쓰였는가
- [ ] 가결산·고객 제공 수치에 기준이 병기됐는가
- [ ] 양호 영역은 한 줄, 리스크 영역은 상세한가
- [ ] 강점 서술이 2~3문장 이내이고 전망성 부연이 없는가
- [ ] 보완사항이 2가지 이하이고 해결 방법을 상세히 쓰지 않았는가
- [ ] 마지막 단락이 수치가 아니라 체계·방향으로 닫히고, 고객의 체크리스트 응답·표현을 받아 주는가
- [ ] 체크리스트 "개선 필요" 5개 이상이면 재무관리 체계 문장이 있는가
- [ ] 한 문장에 주장 두 개를 묶지 않았는가
- [ ] ES 수치가 계정 코멘트·함께 제출되는 산출물과 같은 정의·같은 값인가
- [ ] 서비스·구독 명칭 없이 방향만 암시했는가
- [ ] (v1.2) 모든 수치·판단의 근거가 보고서 지면(Analysis 노출 행·코멘트·체크리스트)에 있는가. Graph·숨김 행·내부 파일에만 있는 수치가 없는가
- [ ] (v1.2) 고객이 이미 운영 중인 체계를 보완사항으로 권하지 않았는가. 체크리스트 "예" 문항과 모순되는 문장이 없는가
- [ ] (v1.2) 스크린샷 등 일부 자료로 고객 내부 체계의 결함을 단정하지 않았는가
- [ ] (v1.2) 고객 제공 정성 정보에 "(제공해주신 자료 기반)"을 문장 끝에 붙였는가
- [ ] (v1.2) 미래 문장이 "지연·악화"가 아니라 "회복·개선"을 주어로 쓰였는가
- [ ] (v1.2) 자본잠식 시점·런웨이 개월·신용등급 같은 내부 진단이 ES에 들어가지 않았는가
- [ ] (v1.2) 분량을 채우기 위해 추가한 문장이 없는가

## 우선순위 (규칙이 충돌할 때)

1. 사실 정확성(지어낸 원인 금지, 원인 분해 근거) — 항상 최우선
